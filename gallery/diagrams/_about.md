# 流程与架构 · diagrams

解释工作流程、交互时序、系统边界、数据关系和事件顺序。按理解任务排列，动画变体紧随静态骨架。

**收录标准**：流程、泳道、时序、状态、上下文、逻辑架构、部署、数据管线、RAG/Agent、ER、依赖与层级。上下文图讲外部关系，逻辑架构讲内部职责，部署图讲运行位置；不得混成一张没有明确层级的技术名词拼图。数值流量桑基图归数据图表，传播对照版式归品牌与排版。

**展示顺序**：流程与决策 → 交互与状态 → 系统与部署 → 数据与AI执行 → 关系与层级 → 集合与事件。共21张，静态/动态对保持相邻。

**语义约定**：所有节点有职责，箭头有明确方向；判断覆盖分支，状态说明终态；重试与Agent循环有预算、错误出口与审批条件。部署边界不等于实际安全验证。时间轴等距仅编码事件顺序，集合面积不编码人数。

**动效约定**：完整结构与文字从首帧可见；动效只强调示例路径，不代表真实在线状态或吞吐量。减少动效模式保留完整静态图。

**维护**：先改 `scripts/build-diagrams.py` 中的节点/端口/关系，运行 `python3 scripts/build-diagrams.py` 和 `node scripts/build-readme.mjs`，再运行 `python3 scripts/check-diagrams.py`；三件套从同一结构生成，避免提示词与图示漂移。
